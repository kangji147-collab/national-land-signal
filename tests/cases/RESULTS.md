## 일치율 결과 (2026-11-12, 사례 20건 · 정답은 AI 초안)

**정답의 출처:** 작성자(사용자)가 "국유재산 매각 기준을 찾아서 AI가 판단해 달라"고 요청해, 국유재산법(제6조·제11조·제27조·제41조·제43조)·시행령(제40조)·하천법 제4조만 근거로 정했다. 규칙표는 보지 않고 정했다. 각 사례 파일의 `expectedReason`에 근거를 적었고 `note`에 "AI 초안, 담당자 검토 전"을 표시했다.
**한계:** PRD의 기준은 "**담당자 판정**과 90% 이상 일치"이다. 이번 정답은 담당자가 아니라 AI가 법령으로 정한 것이라, 이 결과는 "규칙표가 법령 해석과 맞는지"에 대한 점검이며 PRD 기준 2의 공식 확인이 아니다. 실제 국유재산(일반재산)인지, 행정재산으로 쓰이는지는 법령만으로 알 수 없어 일부 사례(예: 서울시청·정부청사)는 가정에 기댔다.

2. **규칙표가 더 엄격한 항목 (4건).** 하천구역·도시자연공원구역·개발제한구역은 규칙표에서 🔴이지만, 정답 초안은 🟡(담당자 확인 필요)로 봤다. 이는 법령만으로는 갈리는 정책 판단이라 **담당자 결정**이 필요하다. (안전한 방향의 차이)
3. **지목 유지·건물 용도는 규칙표가 보지 못한다 (2건).** 지목 "유지"는 🟡, 판정은 건물 용도(청사 등 공용재산)를 쓰지 않는다. 지목 규칙 보강 또는 건물 용도 규칙이 필요하다.

## 정답 확정 (2026-11-12, 사용자 결정)

남은 5건의 정답을 사용자(작성자)가 다음 3가지로 결정해서 모두 🟡로 바꿨다. (각 사례 파일의 `note`에 변경 이력, `expectedReason`에 이유를 적었다.)

1. **농지(밭·논)는 담당자 상담 필요(🟡)** — land-05, land-14
2. **정비구역 안의 땅은 🟡** — building-05

**읽는 법 (중요):** 이 100%는 "AI가 만든 규칙표"와 "AI 초안에 사용자 결정 3가지를 더한 정답"이 일치한다는 뜻이다. 이미 한 번 규칙에 맞춰 정답 5건을 고쳤으므로 규칙의 성능을 그대로 보여 주는 숫자는 아니다. PRD 기준(담당자 판정과 90% 일치)을 공식으로 확인하려면 **담당자가 정답을 검토**하고, 보강에 쓰지 않은 **새 주소 사례**로 다시 시험해야 한다.

## 🟢 기능 시험용 사례 5건 추가 (2026-11-12, 사용자 요청)

정답이 🟢인 사례가 20건 중 1건뿐이라 🟢 판정 경로가 거의 시험되지 않아서, 사용자가 "실제 사례는 모르니 AI가 골라 달라, 기능만 시험해 달라"고 요청해 **land-16~20** 5건을 더했다. (사례는 총 25건: 토지 20 + 건물 5)

- 고른 기준: 작은 일반 대지(지목 대, 95~284㎡), 주거지역, 걸린 지역지구가 모두 이용·개발 제한형이며 **규칙표에 있는 이름**인 곳. 인천 구월동·원주 단계동·부천 중동·전주 금암동·창원 용호동.
- 정답은 모두 🟢(AI 초안). 실제 국유재산인지는 확인하지 않았다.
- 결과: **25/25건(100%)**, 위험한 오판정 0건, 조회 실패 0건. 새 5건 모두 🟢로 판정되어 🟢 판정 경로와 주소 조회~판정 이어서 시험이 동작함을 확인했다.
- **한계:** 규칙표에 있는 이름만 걸린 곳을 골랐으므로 "규칙표에 없는 지역지구가 나오면 🟡" 경로나 규칙표의 빈틈은 이 5건으로 시험되지 않는다. 기능 확인용이며 정확도 근거로 쓰면 안 된다. 담당자 검토 때 실제 사례로 교체하거나 보완한다.
- 시험 기준 변경: 사례가 20건 이상이면 일치율 90%를 확인하도록 `cases.test.ts`·`e2e-cases.live.test.ts`·`check-cases.mjs`(토지 목표 20건)를 고쳤다.

## 공개된 '국유재산 처분기준'으로 다시 맞춤 (2026-11-12, 사용자 요청)

**사례 정답 확인:** 25건을 이 문서 기준으로 다시 훑어 **land-09(강릉시 6,426㎡, 기준 3,000㎡ 초과)만 🟢→🟡로 바꿨다**(제5조). 나머지는 그대로다. 결과: **25/25건 일치, 위험한 오판정 0건, 조회 실패 0건**(규칙만 시험·주소 조회부터 판정까지 이어서 시험 모두).

**면적 규칙의 한계:** 문서의 기준은 "경계가 맞닿은 국유 일반재산 **전체**(일단의 토지)"의 면적이다. 앱은 필지 하나의 면적만 알 수 있어서 **필지 하나가 이미 기준을 넘는 경우만** 잡는다. 이웃한 국유지와 합쳐 기준을 넘는 경우는 알 수 없다.

**문서만으로는 알 수 없어 사람 확인이 남는 것 (2가지):**
1. 그 땅이 실제 국유 일반재산이고 캠코가 "처분형"으로 분류했는지 (제4조①11: 개발형·활용형·보존형·처분형 중 처분형만 매각). 공개되지 않은 내부 분류다.
2. 제4조①2("다른 법률에 따라 처분이 제한되는 경우")가 구체적으로 어떤 지역지구에 해당하는지 (정비구역·문화유산구역 등 개별 법령 판단). 현재 규칙은 이런 구역을 🟡로 둔 AI 초안이다.
이 두 가지는 앱의 안내 문구("참고용, 최종 매각 여부는 한국자산관리공사 심사로 결정")가 이미 다루는 범위다.

## 판정 정확도 시험 방법 (사례가 채워지면)

사례 파일(`tests/cases/land-01~15.json`, `building-01~05.json`)에 **작성자가 정한 정답**과 실제 주소·질문 답을 채운 뒤:

1. **규칙만 시험** (화면·공공 API 없이, 예시 규칙표 기준): `npm test -- tests/cases.test.ts`
   — 사례 20건이 모두 채워지면 일치 90% 이상·위험한 오판정 0건을 자동으로 확인한다.
2. **주소 조회부터 판정까지 이어서 시험** (실제 브이월드·건축HUB·Supabase 규칙표):
   `RUN_LIVE_TESTS=1 npm test -- tests/live/e2e-cases.live.test.ts` (PowerShell: `$env:RUN_LIVE_TESTS=1; npm test -- tests/live/e2e-cases.live.test.ts`)
   — 사례마다 주소 검색 → 토지 정보 → (건물) 건축물대장 → 판정을 거쳐 정답과 비교하고, 결과 표를 출력한다. `E2E_REPORT=파일경로`를 주면 표를 저장한다.
   — 주소 검색이 엉뚱한 필지를 고르면 사례 파일에 `"pnu": "필지번호 19자리"`를 적어 고정할 수 있다.
   — 하루 사용 횟수(20회)는 쓰지 않지만, 공공 API 호출 한도는 쓴다.

두 시험 모두 사례 파일에서 `expectedSignal`·`extracted.landCategory`·`extracted.zone`(규칙만 시험), `extracted.address`(이어서 시험), `answers`가 채워진 사례만 채점한다.
